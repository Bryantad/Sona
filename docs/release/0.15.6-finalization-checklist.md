# Sona 0.15.6 Finalization Checklist

This checklist turns the remaining 0.15.6 release work into an auditable
sequence. It is intentionally not a release claim: 0.15.6 is not final until
the version sweep, final artifacts, and matching-host certification have all
completed from the final source state.

## Preconditions

- Use the authoritative worktree:
  `E:\SonaProofBuild\sona-0154-release-build`.
- Preserve unrelated work in the original `E:\SonaMinimal` checkout.
- Get explicit user authorization before any commit, merge, tag, push, GitHub
  release publication, or package publication.
- Get explicit user authorization before the atomic version sweep from `0.15.5`
  to `0.15.6`.
- Keep Proof Mode wording in user-facing content. Do not introduce alternate
  product branding for the feature.
- Do not claim Linux, macOS, Android, or iOS support from artifact names alone.

## 1. Pre-sweep source health

Run these before changing version metadata:

```powershell
git status --short --branch
python -m pytest -q -ra --junitxml=E:\SonaProofBuild\release-artifacts\sona-0156-pre-sweep.xml
python tools\validate_release_metadata.py --version 0.15.5
node vscode-extension\node_modules\typescript\bin\tsc -p vscode-extension
node vscode-extension\node_modules\esbuild\bin\esbuild vscode-extension/src/extension.ts --bundle --minify --platform=node --format=cjs --target=node20 --supported:template-literal=false --external:vscode --outfile=vscode-extension/out/extension.js --log-level=warning
node vscode-extension\scripts\smoke-ai-console.js
node vscode-extension\scripts\smoke-guide.js
npm --prefix vscode-extension audit --omit=dev --audit-level=high
git diff --check
```

Expected evidence:

- full local Python suite passes except documented environment-only skips;
- current `0.15.5` metadata remains internally consistent before the sweep;
- extension TypeScript, bundle, and smokes pass;
- production extension audit reports no high-severity vulnerabilities;
- whitespace check has no errors.

## 3. Final local Windows artifacts

Use fresh output directories outside the checkout, for example:

```powershell
$out = 'E:\SonaProofBuild\release-artifacts\sona-0.15.6\release-candidate'
$portableIn = Join-Path $out 'portable-input'
$portableOut = Join-Path $out 'portable-output'
$nativeOut = Join-Path $out 'native-output'
$verifyOut = Join-Path $out 'verification'
```

Build and inspect portable artifacts:

```powershell
python -m build --outdir $portableIn
vscode-extension\node_modules\.bin\vsce.cmd package --out (Join-Path $portableIn 'sona-ai-native-programming-0.15.6.vsix')
python tools\release\platform_release_0156.py portable `
  --wheel (Join-Path $portableIn 'sona_lang-0.15.6-py3-none-any.whl') `
  --sdist (Join-Path $portableIn 'sona_lang-0.15.6.tar.gz') `
  --vsix (Join-Path $portableIn 'sona-ai-native-programming-0.15.6.vsix') `
  --output-dir $portableOut
```

Build and inspect the Windows Native Core archive from the final source. Ensure
the Visual Studio `dumpbin.exe` directory is on `PATH` for dependency
inspection:

```powershell
python tools\release\platform_release_0156.py native `
  --platform windows `
  --architecture x86_64 `
  --target x86_64-pc-windows-msvc `
  --output-dir $nativeOut
```

Run the final local Windows verifier:

```powershell
python tools\release\platform_release_0156.py verify `
  --wheel (Join-Path $portableOut 'sona_lang-0.15.6-py3-none-any.whl') `
  --sdist (Join-Path $portableOut 'sona_lang-0.15.6.tar.gz') `
  --vsix (Join-Path $portableOut 'sona-ai-native-programming-0.15.6.vsix') `
  --native-archive (Join-Path $nativeOut 'sona-native-0.15.6-windows-x86_64.zip') `
  --report (Join-Path $verifyOut 'sona-windows-x86_64-python-3.12.json')
```

This proves local Windows artifact consistency only. It does not prove Linux or
macOS compatibility.

## 4. VS Code install and visual acceptance

Install the final VSIX into an isolated VS Code profile:

```powershell
code --user-data-dir <isolated-user-data> --extensions-dir <isolated-extensions> --install-extension <final-vsix> --force
code --user-data-dir <isolated-user-data> --extensions-dir <isolated-extensions> --list-extensions --show-versions
```

Then perform the real editor-host acceptance check that automated smokes cannot
replace:

- open a saved `.sona` file containing the `quant` / `quantity` flagship case;
- confirm canonical diagnostics appear;
- open Sona Guide explanation from the diagnostic;
- preview the deterministic edit;
- change the file while confirmation is pending and confirm stale protection;
- re-run with the original file and apply the edit;
- verify that complete diagnostics are not deleted by Focus Mode;
- run a Proof Mode receipt explanation through the CLI-backed extension path.

Record the VS Code version, extension version, host OS, and exact result in the
implementation report.

Dispatch or tag the 0.15.6 platform workflow only after the final source state
is ready and the user has authorized the required GitHub mutation:

```text

```

Required evidence:

- portable artifact job passes;
- Windows x86-64 Native Core job passes;
- Linux x86-64 musl Native Core job passes;
- Linux ARM64 musl Native Core job passes;
- macOS Intel Native Core job passes;
- macOS Apple Silicon Native Core job passes;

If GitHub billing, runner availability, or account state blocks execution,
record that as a blocker. Do not convert local Windows evidence into a
Linux/macOS certification claim.

## 6. Final publication package

After all required local and hosted gates pass:

- assemble `SHA256SUMS.txt`;
- compare every artifact hash against the release manifest;
- ensure `RELEASE_NOTES_v0.15.6.md` no longer reads like a draft once final
  evidence exists;
- confirm the assurance boundary still states that current Proof Mode is not a
  signature, signer identity, trusted timestamp, trusted hardware proof, remote
  attestation, or trusted OS proof;
- only then create the final commit/tag/release/publish steps, with explicit
  user authorization.

## Remaining non-release blockers

These must either pass or be explicitly deferred before calling 0.15.6 complete:

- final full local suite after the version sweep;
- final extension build/smoke/audit after the version sweep;
- real VS Code visual walkthrough;
- final wheel/sdist/VSIX/Native rebuilds;
- Windows local artifact verifier from final source;
- Linux/macOS matching-host certification;
- final review that Sona Guide never changes canonical facts, diagnostics,
  Proof Mode receipts, or Guardian verification outcomes.

See also `docs/release/0.15.6-acceptance-audit.md` for the current
requirement-by-requirement status map. The audit is a checkpoint, not a
substitute for final release evidence from the swept source state.
