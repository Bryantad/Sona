## Compatibility risks and duplicated behavior

1. Module selection prefers a workspace `.sona_modules/<name>.smod`, then the
   shipped `.smod`, then `native_<name>.py`, then `<name>.py`. Changing this
   precedence would break supported workspace overrides.
2. `fs` and `io` independently implement reads, writes, appends, existence,
   directory creation, listing, removal, copy, and move. `io.input` also mixes
   console input into the file API.
3. `native_io` converts failures to `{"error": ...}` maps, while several
   helpers return `false` or `nil`. Callers cannot distinguish absence from
   permission, encoding, confinement, or transport failures.
4. `http.py` is a direct Python implementation with inconsistent retry/error
   behavior between verbs. It omits `ok` and final `url`, treats some HTTP
   statuses as transport failures, and has no runtime capability binding.
5. Public export discovery is inconsistent: Python `__all__`, `.smod`
   declarations, documentation, the 145-entry manifest, and the 85-entry
   catalog disagree. For example, JSON `parse`/`stringify` and string
   `starts_with`/`ends_with` exist in `.smod` but not Python `__all__`.
6. `date.sleep` overlaps `time.sleep`; collection randomization overlaps
   `random`; JSON file helpers overlap `fs`; old spellings such as `read`,
   `write`, `mkdir`, `randint`, and `random` lack a canonical migration record.
7. The native VM can import and execute user `.smod` modules but has only one
   host function (`print`). It has no standard-library host registry and its
   default capabilities deny filesystem and network access.
8. Native module function values do not capture module globals. Stateful
   wrappers such as `random.smod` therefore cannot be made native merely by
   copying the Python-side `.smod` file.
9. Python and Rust diagnostics have compatible schema concepts but separate
   constructors. Raw host exceptions currently lose the stdlib operation ID
   and active call span when converted by the interpreter.

## File-level implementation map

- Extend the existing uppercase manifest to schema 2 and derive the catalog
  from it; do not add a case-colliding lowercase manifest.
- Add shared Python stdlib diagnostic/capability helpers and bind private
  bridges to the active interpreter.
- Consolidate public `.smod` wrappers around canonical `fs`, `json`, `io`,
  `stdin`, `random`, and string names while retaining quiet aliases.
- Add a native host-module registry inside `sona-vm`, preserving workspace
  module precedence and explicit capability defaults.
- Add focused stdlib contract, failure, HTTP mock-server, safe-mode, and
  Python/native conformance suites before changing version metadata.

This audit is the Phase 0 boundary. It records existing behavior; it does not
claim any 0.15.4 capability as implemented.
