# Sona 0.15.5 Adoption Documentation Plan

Status: implemented and validated

## Audit

The current root README opens by calling Sona an "AI-native" language and then
lists implementation surfaces. It does not answer the first-time reader's core
questions in order: why Sona exists, how it differs from ordinary Python,
what Proof Mode records, what can be built today, and how to try it.

The detailed getting-started guide already uses the intended evidence-first
positioning and states the self-hash limits. The root README should adopt that
plain-language framing and route technical readers to the existing schema,
canonicalization, and implementation references instead of leading with them.

## Change

The first README screen will:

1. define Sona as a simple language for software that can provide evidence of
   what it did;
2. explain Proof Mode's privacy-conscious evidence and Guardian's policy role;
3. answer "Why Sona?" and "Why not just Python?" without attacking Python;
4. list realistic current workflows, including explicit Native HTTP limits;
5. provide the shortest ordinary-run path and route Proof users to the tested
   ten-minute guide; and
6. keep parser, AST, Rust, canonicalization, and schema details in technical
   documentation.

The change will preserve 0.15.4 release metadata until the final atomic 0.15.5
version sweep.

## Implementation result

The root README now opens with the evidence-first description, separates
ordinary execution from Proof Mode, explains Guardian's policy role, lists
realistic current uses and Native HTTP limits, and routes new users to the
tested getting-started path. The final atomic metadata sweep has since moved
the repository and release documentation to 0.15.5.
