# Sona 0.15.5 Beginner CLI Review

Status: implemented and validated

## Audit result

The CLI already supports the shortest useful first step through `sona run` and
direct `sona file.sona` invocation. Project metadata starts with `sona pkg
init`; it does not scaffold source files. Adding `sona new` in this release
would invent a second project convention without a reviewed template or
directory contract, so it is deferred.

Current file-not-found diagnostics are concise, hide tracebacks, and include a
recovery hint. The largest beginner gap is command discovery:

- top-level help describes Sona as a cognitive language instead of explaining
  the ordinary-run, Proof Mode, and Guardian paths;
- Proof Mode help hides its key capability and Guardian-binding flags behind
  "Native Proof options";
- canonical Guardian subcommands have no one-line explanations; and
- no-argument help does not show the next evidence and policy steps.

## Planned changes

1. Replace the top-level description and examples with plain-language run,
   Proof Mode, verification, and Guardian guidance.
2. State that ordinary `sona run` creates no Proof Mode receipt.
3. Expand Proof Mode help with the no-fallback rule, new-path rule, capability
   flags, Guardian binding, and integrity/authentication distinction.
4. Add beginner-facing help for Guardian's read-only and mutating commands.
5. Add subprocess tests for stable help and error guidance.

No Sona syntax, project scaffolder, trust primitive, or command alias is added.

## Implementation result

Top-level, Proof Mode, and Guardian help now expose the ordinary-run,
evidence, verification, and policy paths in plain language. File-not-found and
new-receipt-path failures remain concise and traceback-free. A `sona new`
scaffolder remains deliberately deferred because no project-template contract
was approved. Focused beginner CLI and onboarding validation passes with
8 tests.
