# Sona 0.15.5 LSP stabilization plan

Status: implemented and validated

## Scope

This phase makes the existing Python language server a narrow, dependable
developer surface. It does not change Sona syntax and it does not introduce a
second parser, diagnostic taxonomy, package manager, or language-server
implementation.

The 0.15.5 support boundary is:

| LSP feature | 0.15.5 status | Contract |
| --- | --- | --- |
| Diagnostics | Required | Use the canonical frontend and existing Sona diagnostic IDs and spans. |
| Hover | Required | Return documented stdlib or conservative local-declaration information; otherwise return no result. |
| Completion | Required | Offer context-relevant stdlib modules, stdlib members, language keywords, and local declarations. |
| Go to definition | Target | Resolve unambiguous declarations in the current document only. |
| Document symbols | Target | Report conservative top-level imports, functions, classes, and variables. |
| Rename | Deferred | No symbol table or scope model is certified for safe edits. |
| Formatting | Deferred | No canonical formatter is certified; the current textual rewrite is unsafe. |
| References | Deferred | Lexical matches are not a reliable reference model. |

## Pre-change architecture

- `sona/lsp_server.py` contains the pygls server, protocol handlers, stdlib
  documentation discovery, and ad hoc symbol scanning in one module.
- `sona.developer_intelligence.frontend.analyze_frontend` is the canonical
  diagnostic entry point used by both CLI and LSP. The LSP maps its schema-1
  IDs, severities, messages, hints, and one-based spans to LSP diagnostics.
- pygls 1.3.1 and lsprotocol 2023.0.1 provide JSON-RPC transport, document
  synchronization, initialize, shutdown, and exit lifecycle handling.
- the VS Code extension starts `python -m sona.lsp_server --stdio` using the
  configured Python interpreter or a workspace virtual environment.
- stdlib completion and hover data are read from the stdlib manifest and from
  packaged `.smod` or Python module documentation.

## Observed baseline

An actual stdio JSON-RPC session completed initialize, initialized, didOpen,
diagnostics publication, completion, hover, definition, document symbols,
shutdown, and exit with process status 0.

The initialize result advertised diagnostics via document synchronization plus
completion, hover, definition, references, document symbols, and formatting.
The malformed test document produced `SONA-PARSE-003` through the canonical
frontend. The focused pre-change tests completed with 14 passing tests and two
known Lark deprecation warnings.

## Gaps

1. References and formatting are advertised even though their handlers are
   purely textual and can return semantically incorrect results or modify
   strings and comments.
2. Definition and document-symbol scanning do not recognize canonical
   `let`/`const` declarations; document symbols also omit classes and import
   aliases.
3. Unknown hover targets return content that implies useful information where
   none is known.
4. General completion returns a large module list without local declarations
   or language keywords, and member lookup does not resolve import aliases.
5. `textDocument/didClose` does not explicitly clear published diagnostics.
6. document URI and source-length details are written to stderr during normal
   editing, which is unnecessary metadata exposure.
7. Existing tests validate diagnostic parity as Python calls but do not test
   framing, capabilities, notifications, lifecycle ordering, malformed
   documents, or server survival over stdio.
8. the public LSP roadmap still describes an older experimental surface and
   does not state the narrow 0.15.5 contract.

## Architecture decisions

### One diagnostic authority

The LSP continues to call the canonical developer-intelligence frontend.
Infrastructure failures are converted to the existing `SONA-PARSE-099`
diagnostic without raw exception text. No LSP-only parser or error IDs are
introduced.

### Conservative local index

Editor navigation uses a small, non-executing lexical index for declarations.
It recognizes only grammar-backed, unambiguous declaration forms and remains
useful while a document is incomplete. It is not called a semantic index and
does not claim cross-file resolution or scope-aware references.

The index must ignore declaration-looking text in comments and quoted strings,
recognize top-level imports, functions, classes, `let`, `const`, and bare
assignments, and retain exact zero-based name ranges. Function parameters and
nested local variables are intentionally outside this phase.

### Fail-closed handlers

Every request must tolerate missing documents, out-of-range positions, and
malformed source without a traceback, malformed JSON-RPC response, or server
exit. When information cannot be established reliably, handlers return an
empty list or no result instead of a guess.

### Honest advertised capabilities

Only implemented and tested features are registered. Rename, formatting, and
references are not advertised in 0.15.5. Removing an unreliable capability is
an intentional compatibility hardening: clients can no longer invoke behavior
that Sona cannot support safely.

## Lifecycle contract

1. `initialize` returns the pygls-managed server identity and only the tested
   feature capabilities.
2. `initialized` enables normal document traffic.
3. `didOpen` and full or incremental `didChange` publish canonical diagnostics.
4. `didClose` publishes an empty diagnostic set for the closed URI.
5. requests against an open malformed document return conservative results and
   do not terminate the server.
6. `shutdown` returns a successful null result, and a following `exit`
   terminates the stdio process with status 0.
7. protocol logs, if any, stay on stderr and never include source text or local
   paths. Normal document operations should not emit per-document logs.

## Implementation order

1. Extract pure position, declaration-index, alias, completion, hover, and
   definition helpers that can be unit tested without transport.
2. keep diagnostics on the canonical frontend and add explicit diagnostic
   clearing on close.
3. register only diagnostics, completion, hover, definition, and document
   symbols; remove references and formatting registration.
4. add pure helper tests for declaration ranges, comments, strings, malformed
   source, aliases, and out-of-range positions.
5. add a real stdio protocol test covering the full lifecycle and every
   advertised feature, including malformed-document recovery.
6. update user-facing LSP documentation to match the tested support matrix.
7. run focused tests, the complete Python suite, lint on changed files, VS Code
   compilation/tests, package audit, and rebuild the VSIX.

## Remaining non-goals

Cross-file indexing, rename, formatting, references, workspace symbols,
semantic tokens, signature help, code actions, Native Core LSP hosting, Native
HTTP, SPM, LSP-specific AI inference, and syntax changes remain outside this
phase.

## Implementation result

The server now advertises only diagnostics, completion, hover, current-document
definition, and document symbols. Those features use the canonical frontend
or conservative non-executing indexing, clear diagnostics on close, and fail
closed for unavailable information. The real stdio lifecycle and malformed
document recovery contract passes with all 5 focused tests.
