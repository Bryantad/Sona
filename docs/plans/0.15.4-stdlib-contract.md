# Sona 0.15.4 Standard Library Contract

Status: implementation contract  
Schema identifier: `sona.stdlib.manifest.schema-2`

## Compatibility policy

The 0.15.4 certified foundation is `collection`, `date`, `fs`, `http`, `io`,
`json`, `math`, `random`, `stdin`, `string`, and `time`. All other 0.15.3
modules retain their importability and stability. Compatibility aliases remain
silent through the 0.15.x line.

Workspace `.sona_modules` continue to override shipped modules. Private
`native_*` modules cannot be imported by application code.

## Canonical surface

| Module | Canonical exports | Compatibility treatment |
| --- | --- | --- |
| `collection` | `first`, `last`, `take`, `drop`, `flatten`, `unique`, `frequencies`, `push`, `pop` | Other existing helpers remain individually classified |
| `date` | `today`, `from_timestamp`, `parse`, `format` | `date.sleep` delegates to `time.sleep` |
| `fs` | `read_text`, `write_text`, `append_text`, `exists`, `is_file`, `is_dir`, `list_dir`, `create_dir`, `remove`, `rename`, `copy` | `read`, `write`, `append`, and `mkdir` remain aliases |
| `http` | `get`, `post`, `put`, `patch`, `delete` | Existing helpers remain preview compatibility APIs |
| `io` | `write_stdout`, `write_stderr`, `flush` | File methods delegate to `fs`; `input` delegates to `stdin.read` |
| `json` | `parse`, `stringify` | `loads`, `dumps`, `load`, and `dump` remain aliases/helpers |
| `math` | existing constants and core arithmetic/power/root/clamp/rounding/minimum/maximum operations | Existing advanced helpers retain their status |
| `random` | `seed`, `integer`, `choice`, `shuffle`, `float` | `randint` and `random` remain aliases |
| `stdin` | `read(prompt=nil)` | New public module backed by private console input |
| `string` | existing helpers plus `starts_with` and `ends_with` | `startswith` and `endswith` remain aliases |
| `time` | `now`, `sleep`, `monotonic`, `timestamp` | Existing parsing/formatting helpers remain available |

## Values and effects

- Text filesystem operations use UTF-8. Writes return the number of Unicode
  scalar values written. `list_dir` is sorted and returns forward-slash
  relative names. Missing `remove` targets return `false`; other failures are
  diagnostics. Recursive directory removal remains the 0.15.x default.
- `json.stringify(value, indent=nil)` uses deterministic object-key ordering.
  The indent is `nil` or a non-negative integer.
- `random` uses the existing Sona LCG on both engines. `integer` is inclusive,
  `float` returns a value in `[0, 1)`, and `shuffle` returns a new list.
- HTTP methods accept `(url, options=nil)`. Supported options are `timeout`,
  `headers`, mutually exclusive `body`/`json`, `follow_redirects`, and
  `max_body_bytes`. Defaults are 10 seconds, redirects enabled, and 10 MiB.
- HTTP responses contain `status`, `ok`, `body`, lower-cased `headers`, and
  final `url`. Non-2xx status is a response, not a transport exception.

## Runtime capabilities

Normal Python-compatible runs preserve current process filesystem/network
access. Safe mode confines reads to the project root and denies secret reads,
writes, and network access.

Native defaults remain console-only. The standalone CLI uses explicit
`--allow-fs-read`, `--allow-fs-write`, and `--allow-network` flags. Native HTTP
is importable but returns the reviewed `SONA-HTTP-005` unavailable diagnostic
for 0.15.4.

## Diagnostic registry

- `SONA-FS-001..006`: invalid argument, missing path, operation failure,
  permission denial, capability denial, encoding failure.
- `SONA-HTTP-001..005`: invalid request, timeout, transport failure, body or
  decoding limit, capability/unavailable.
- `SONA-JSON-001..003`: parse, serialization, options.
- `SONA-IO-001..003`: input, output, capability.
- `SONA-TIME-001..003`: invalid value, timezone/format, duration.
- `SONA-STDLIB-001..003`: unsupported export, contract/type failure, private
  module access.

Diagnostics carry the active call span and a sanitized operation target. They
never contain file contents, HTTP bodies, credentials, or URL secrets.

## Completion rule

Every canonical PASS export requires positive Python and native fixtures.
Every diagnostic ID requires an exact negative fixture. Unsupported native
behavior is a capability result, not parity. Version metadata changes only
after the existing suite, examples, probes, locked Rust gates, clean-install
tests, and stdlib conformance gates pass.
